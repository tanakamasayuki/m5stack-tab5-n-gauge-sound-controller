# Nゲージ サウンドボックス 要件定義書

**バージョン：** 0.1（ドラフト）
**対象：** M5Stack Tab5

## 1. コンセプト

KATO製パワーパックで普段どおり運転しながら、Tab5 を**カジュアルなサウンドボックス**として使う。

- **ボタンを押せば音が鳴る**
- **電車の種類を変えれば音も変わる**（実際に走っている車両とは連動しない。音のセットを選ぶだけ）
- **速度連動は、粗くてもいいので可能な範囲で行う**（車両ごとの厳密な調整は求めない）

操作感と機能の範囲は、LEGO Powered Up アプリの列車操作画面くらいを目安にする。

### 参考：KATO サウンドボックス（22-102）との位置づけ

KATO の純正品は、パワーパックと線路の間に挟んで、走行状態に合わせた走行音を鳴らす製品である。

| 項目 | KATO サウンドボックス | 本プロジェクト |
|---|---|---|
| 価格 | 本体 35,200円（税込、希望小売価格）、サウンドカードは1枚 約2,750〜3,300円 | Tab5 と U200 の費用のみ |
| 接続位置 | パワーパックと線路の間 | パワーパックの入力（ACアダプタ側） |
| 走行との同期 | 実際の走行状態に同期する（電流と PWM パルスを使うとされる） | 入力電流だけを使い、粗く連動させる |
| 操作 | 押しボタン6個、ボリューム（音量・起動電圧・音同期など） | タッチ画面（ボタン数の制限なし） |
| 音源 | 車種別のサウンドカード（有料） | 自分で作れる音源パック（初期音源は CC0） |

純正品には「起動電圧」や「音同期」の調整ボリュームがある。本プロジェクトでは、こうした調整を自動化して、なくすことを目指す（4章）。

## 2. 前提とシステム構成

```
ACアダプタ ─[DCジャック(オス)]─ 中継 ─[DCジャック(メス)]─ KATO パワーパック スタンダードSX ─ 線路
                                   │
                              M5Stack U200 (INA226)
                                   │ Grove (I2C)
                              M5Stack Tab5
```

- パワーパックは KATO スタンダードSX を使う。入力は普通のDCジャック。
- ACアダプタとパワーパックの間にDCジャックの中継を挟み、そこに M5Stack U200 を入れて**入力電流**を測る。
  - 入力側は電圧がほぼ一定なので、使う情報は電流だけ。
  - 線路側と違って極性が反転しないので、絶縁の問題が起きにくい。
  - U200 は 10A 版を使う。
    - パワーパックの定格出力は最大 1.2A で、1A 版では最大負荷やショート時に測定範囲を超えるため。
    - 10A 版は分解能が粗くなるが、粗い連動が目的なので許容する（実際に足りるかは実験 E1 で確認する）。
- 列車本体とパワーパックは改造しない。
- 当面は、パワーパック1台につき1編成だけを走らせる前提とする。

## 3. 機能要件

優先度の意味：**Must** ＝ 必須、**Should** ＝ できるだけ入れる、**Could** ＝ 余力があれば入れる。

| ID | 要件 | 優先度 |
|---|---|---|
| F-01 | タッチボタンで効果音を鳴らせる（警笛・汽笛、ドア開閉、発車ベル・メロディ、車内アナウンスなど） | Must |
| F-02 | 車両の種類（音のセット）を選べる。選んだ車両に合わせて、全部の音が切り替わる | Must |
| F-03 | 走行音を鳴らしながら、効果音を重ねて鳴らせる | Must |
| F-04 | 音量を調整できる | Must |
| F-05 | 電流から走行状態（停止・発進・走行中・減速）を判定して、走行音を自動で切り替える | Must（実現できるかは実験で判断） |
| F-06 | 走行中の電流の大きさに合わせて、走行音を粗く連動させる（数段階、または音の高さや音量を連続的に変える） | Should（実現できるかは実験で判断） |
| F-07 | 電流の大きさをメーター風に表示する（LEGO アプリのスピードメーターに当たるもの） | Should |
| F-08 | 「駅到着」ボタンを1回押すと、ドア開閉音・アナウンス・発車ベルなどを順番に流す | Could |
| F-09 | 雨や風などの環境音を流せる（LEGO アプリの天候切り替えに当たるもの） | Could |
| F-10 | 音源を「音源パック」（車両1種類分の音一式）単位で管理する。利用者が自分で作り、microSD にコピーするだけで追加できる | Must |
| F-12 | 初期音源として、CC0（パブリックドメイン）の音源を詰め合わせた音源パックを同梱する | Must |
| F-11 | 電流を検出できないとき（U200 未接続など）でも、タッチ操作による再生はできる | Must |

## 4. 設計原則

- **車両ごとの調整はしない。**
  - 停止時の電流は、自動でゼロ点として扱う。
  - 電流の大きさは、運転中に見た最大値などをもとに自動で正規化する。
  - 利用者にしきい値を設定させない。
  - 全体共通の「感度」設定を1つだけ置くかどうかは、実験（E2・E3）の結果を見て判断する。
- **連動は粗くてよい。**
  - 判定が多少ずれても、違和感が出にくい音の作りにする。たとえば、音を急に切り替えずにクロスフェードさせる。
- **うまく判定できないときは、機能を一段落として動かす。**
  - 速度連動がうまくいかなければ、状態連動（F-05）だけにする。
  - 状態連動もうまくいかなければ、手動の操作だけにする。

## 5. 音源パック

- **1パック ＝ 1つのフォルダ**とする。中身は、音声ファイルと、それを説明するマニフェスト（設定ファイル）。
- **マニフェストに書くこと：**
  - パックの名前とアイコン
  - ボタンと音声ファイルの対応、ボタンの表示名
  - 走行状態（停止・発進・走行中・減速）ごとの走行音
  - 速度連動の方法（ループの再生速度を変える、段階ごとの音をクロスフェードする、など）
  - 音ごとのライセンスとクレジット
- **プログラミングをしなくても作れること。** テキストエディタで書けて、PC 上で中身をチェックできる手段も用意する。
- **同梱する初期パックの音源は、CC0 のものだけにする。**
  - CC0 の素材が見つからない音（日本語の車内アナウンス、発車メロディなど）は、自作して CC0 で公開する。作り方は、自分で合成する、自分で録音する、などを想定する。
  - BY・NC など、条件の付いたライセンスの素材は同梱しない。利用者が自分のパックで使うのは自由。
  - 初期パックの車両の種類は、あらかじめ決めない。「それっぽい」CC0 音源がそろった車両から、パックにしていく。

## 6. 非機能要件

- サウンドボックスの動作が、列車の運転に影響しないこと。
- ボタンを押してから音が鳴るまでの遅れは、体感で気にならない程度にすること（目標値は実験 E4 で決める）。
- 特別な設定をしなくても、電源を入れればすぐ使えること。

## 7. 対象外

- アプリからの列車制御（速度・進行方向・ライト）
- DCC
- 実際の速度の測定・推定
- 列車の位置検出
- 進行方向の検出
- 同じ線路を複数編成で走らせたときの判定

## 8. 未決事項

- 画面デザインとボタン配置
- CC0 音源の選定（そろった車両から、初期パックにする）
- 全体共通の「感度」設定を置くか（実験 E2・E3 のあとで判断する）
- 音声ファイルの形式と、マニフェストの書式
- 音の出力先（内蔵スピーカーか、外部スピーカーか）

## 9. 開発環境（決定事項）

- Arduino（arduino-cli、`sketch.yaml` のプロファイルでコアとライブラリのバージョンを固定する）
  - 実機：`esp32:esp32:m5stack_tab5`、M5Unified、M5GFX
- 画面：[LGFXScreenBuilder](https://github.com/tanakamasayuki/LGFXScreenBuilder)
- テスト：pytest-embedded と Arduino CLI。構成は arduino-library-release-toolkit に合わせる。
  - `lang-ship:host` プロファイル：ロジック（状態判定など）を PC 上で検証する。実験で記録した CSV を入力にする。
  - `m5stack_tab5` プロファイル：実機で検証する。
